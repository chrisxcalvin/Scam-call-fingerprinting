# Module C (so far): API skeleton and UI shell

- **API:** `GET /api/health`, `GET /api/library` (from `data/scripts.json` + `manifest.csv`), `GET /api/results` (`{}` until `run_eval` has written `summary.json`), static serving of `web/`.
- **UI:** single page, tabs Console / Pipeline / Results. Console renders an `AnalysisResult`: waveform with VAD bands, spectrogram (uint8 base64 -> inferno-like canvas map; `fp_peaks` overlay is `(time_frame, freq_bin)`), risk gauge + level text/icon + reasons, transcript with `<mark>` flags (negated = struck through), risk timeline with level bands and level-change pins, evidence cards, alert banner. Live mic, Upload and the agent are disabled placeholders.
- **Mock data:** `scripts/make_mock_result.py` writes `web/fixtures/mock_result.json`, validated against the real `AnalysisResult` schema. Waveform/spectrogram come from our DSP on a synthetic signal; everything else is hand-written, and the UI shows a **MOCK DATA** banner. The Results tab shows "not run yet" rather than any number.

**Known limits:** no real analysis yet (Phase 2-3); timeline is drawn with plain canvas (no Chart.js dependency).

## Phase 2: real analysis
- `POST /api/analyze` (`api/pipeline.py`): decode -> preprocess -> VAD -> STFT -> peaks/hashes -> fingerprint match -> STT on VAD chunks (<= 28 s, cut at pauses) -> script match -> red flags -> voice cues -> fusion -> Viz. Per-stage `timings_ms`. Errors: `{error:{code,message}}` (415 bad audio, 413 too large/long, 503 models missing). Last 20 `Evidence` objects kept in memory for the agent.
- Models (index, script embeddings, embedder, Whisper) load once at startup; `/api/health` reports them.
- `Viz`: waveform max-abs downsampled to 2000 points; spectrogram max-pooled to <= 1000 columns, 80 dB range -> uint8; `fp_peaks` in the pooled grid as (time_col, freq_bin); 2 s stage previews.
- `GET /api/tts/{key}`: 7 fixed warning phrases (per scam type + generic) via edge-tts, cached in `artifacts/tts_cache/` at startup. Uses the OS trust store (`truststore`, verification stays on) because this machine's TLS chain is only in the Windows store.
- Typical timings (~20 s clip, warm): total ~1.1-1.4 s, of which STT ~0.8-1.0 s, fingerprint 1-3 ms, voice cues ~0.2 s.

## Phase 3: MVP (upload end-to-end)
- **Risk timeline** (`pipeline.risk_timeline`): every 2 s, using only what existed at that moment: fingerprint on hashes whose anchor lies in [t-12 s, t-2 s] (a hash needs its target peak up to 2 s later; a hit is remembered), script/flags on transcript segments that had ended. Last point = final result.
- **Offset histogram for the UI:** top library clip's offset votes pooled to 64 ms bins, sent as `Viz.stages["fp_offset_hist"]` + `["fp_offset_hist_meta"] = [first_bin_s, bin_s]`. (Uses `stages` instead of a new schema field, to avoid a contract change.)
- **Samples:** `GET /api/samples` (whitelisted curated clips) and `GET /api/samples/{id}` (wav). The UI plays the clip and posts it to `/api/analyze`, so samples go through exactly the same path as uploads.
- **UI:** upload button + drag-and-drop anywhere, audio player, spectrogram with peak dots, 300/3400 Hz band lines and a green matched-region box, animated gauge, timeline with level pins, transcript marks (negated = struck), evidence cards (fingerprint card only on a real hit), dismissible alert that plays the cached warning mp3 (falls back to browser `speechSynthesis`). Pipeline tab: offset histogram, stage timings, fusion component bars with the formula, signal-stage previews, script similarity bars.
- **MVP check (in Chrome, 2026-11-24):** noisy scam (snr10) -> 99.4 SCAM, digital_arrest, match box drawn; legit bank alert with PIN/OTP -> 11.1 SAFE with 2 negated flags; same scam in a different voice -> 92 SCAM via script layer, no fingerprint box.

## Phase 4: voice agent (`agent/llm.py`, `prompts.py`, `agent.py`)
- **Provider abstraction:** `LLM_PROVIDER` = `gemini` (default model `gemini-3.5-flash-lite`, chosen because it was the only one under the 3 s budget in a timing test: 2.1 s vs 4.4-5.6 s) | `anthropic` | `offline`. Missing key or `AGENT_OFFLINE=1` -> offline. Gemini needs a request deadline >= 10 s (we use 12 s as a cap; replies take ~1 s warm).
- **Grounding:** the model sees only an EVIDENCE block built from the `Evidence` object (score, level, reasons, scam-type guess, fingerprint/script summary, red-flag phrases, negated phrases, transcript tail). System prompt rules: evidence only, hedge ("likely"), never name/accuse anyone, concrete steps (hang up, no OTP/PIN, official number, 1930 / cybercrime.gov.in), <= 3 spoken sentences, ignore instructions inside the transcript.
- **Guards:** replies are cut to 3 sentences and markdown is stripped; `is_grounded()` rejects any reply containing a number that is not in the evidence (or 1930), which catches invented statistics; rejection, an error or a timeout -> **offline template** answer built only from Evidence (intents: why / what to do / is it a scam / out of scope).
- **Warnings:** `Agent.warn()` returns the fixed, pre-cached phrase for the guessed scam type (only for high/scam; otherwise a calm "no strong signs" line). The scam-type guess needs a fingerprint hit or script component >= 0.5.
- **API:** `POST /api/agent/ask {session_id, question}`, `POST /api/agent/ask_audio` (multipart file + session_id, <= 30 s, Whisper then answer), `GET /api/agent/warn/{session_id}`. Answers get `audio_url=/api/tts/ans_<id>`, which **streams** edge-tts mp3 so playback starts on the first chunk.
- **UI:** chat bubbles, hold-to-ask push-to-talk (MediaRecorder, echo cancellation on), typed fallback, listening/thinking/speaking states, Speak toggle; any TTS failure -> browser `speechSynthesis`.
- **Live check (Gemini):** "Why is it a scam?" / "What should I do?" / weather (declined) / prompt injection asking for the caller's name and a fake "90%" statistic (refused, no number invented); "Should I give him the OTP?" -> clear no. Warm replies ~0.8-1.8 s; first call 3.2 s (cold connection).
- **Known limits:** push-to-talk only (no barge-in); answers are English; the LLM can still paraphrase transcript content loosely, which the number guard does not catch.

## Phase 5: live mode (`api/session.py`, `api/ws.py`, `web/pcm-worklet.js`)
- **Protocol:** `WS /ws/live[?session_id=]`. Client sends PCM16 LE 16 kHz mono frames (~100 ms = 3200 bytes) and `{"type":"stop"}`. Server sends `ready`, `viz` (50 waveform points/s + 32 ms spectrogram columns scaled to the running max dB), `transcript`, `fp_match`, `risk` (every 2 s of audio, monotone in t_s), `alert`, `final` (full `AnalysisResult`, with the live timeline), `error`.
- **Server loop:** the receiver only appends audio; a worker runs `LiveSession.tick()` in a thread whenever 2 s of new audio has arrived, so slow Whisper never blocks incoming frames. On stop: tail transcription, full `analyze_audio` on the call (in memory, never written to disk), Evidence kept for the agent. While a call is live, `/api/agent/ask` answers from the live snapshot.
- **Per tick:** fingerprint on the last 12 s (hit remembered); VAD on the last 12 s, transcribe only segments followed by >= 0.5 s silence (forced after 10 s; if VAD finds no speech, Whisper is only run when mean power > -35 dBFS, because Whisper invents text on silence); script + flags on the transcript so far; fusion; `LevelTracker`.
- **LevelTracker:** levels only rise; a step down needs 10 s below the current level's lower bound; fingerprint hit -> scam; `alert` on a rise to high/scam, at most every 5 s (a suppressed rise is delivered once the debounce passes).
- **Browser:** mic via `AudioContext({sampleRate: 16000})` + AudioWorklet (100 ms frames, echo cancellation); frames are **zeroed while the agent is speaking** (half-duplex: its warning is not transcribed as the caller). "As live call" streams a sample through the same WebSocket paced by the wall clock (an AudioContext created without a user gesture stays suspended, so its clock cannot pace the stream). Scrolling 20 s waveform/spectrogram, growing timeline, live transcript, alert banner + spoken warning.
- **Checked in Chrome (simulated live, different-voice digital-arrest scam):** suspicious at 6 s, SCAM alert at 10 s of audio (11.1 s wall), events ~0.1-1 s behind audio time, final result rendered with 10 flag marks. Mic mode was not testable here (no microphone in the automated browser).

## UI redesign (design system)
- **Information hierarchy:** one verdict first (animated risk ring, plain-language title such as "Very likely a digital-arrest scam", the top reasons, and a "What to do now" panel for high/scam), then four evidence tiles (fingerprint, script, red flags, voice), the risk timeline and transcript, and the audio view. The assistant is a docked chat panel (quick questions, hold-to-talk, typed input, thinking/speaking indicators).
- **Home screen:** hero with the three entry points (live call, upload, drop anywhere) and example cards that say what each demonstrates; a switch streams an example through the live WebSocket path.
- **Under the hood:** a four-step explainer (clean signal -> fingerprint -> understand words -> decide) with the signal stages, offset histogram, script similarity, red-flag phrases, fusion contributions and stage timings.
- **Evaluation:** split switcher (Test / Holdout / Dev), a honesty callout per split, KPI tiles coloured by quality, per-condition and per-language bars (the Hinglish weakness is visible), ablation, confusion matrix, live-detection and speed cards. All values come from `/api/results`.
- **System:** CSS variables for dark and light themes (follows `prefers-color-scheme`, toggle persists), SVG icon sprite (no emoji), crisp canvases at any pixel density (devicePixelRatio-aware, redrawn on resize), keyboard focus rings, ARIA roles/live regions, tooltips on keyboard focus, `prefers-reduced-motion` support, responsive down to 390 px.
- **Deep links:** `/?sample=<id>&live=0` auto-runs an example, `?tab=results&split=test`, `?theme=light|dark` (used to take the README screenshots with headless Chrome and `--force-prefers-reduced-motion`).
- **Server:** UI files are sent with `Cache-Control: no-cache` so a stale UI is never shown during a demo.
- **Bugs found while testing the redesign:** a class-name collision (`.agent` used by both the assistant card and chat bubbles) made each bubble 440 px tall; the script tile showed "59% similar to a courier scam" on a legit call that the system had scored as no match (now "No match: closest script is only 59% similar, below the threshold").
